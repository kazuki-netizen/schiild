# Schiild デモ — 友達とつくるシールト

アトリエを作成して友達を招待し、それぞれのカメラで撮った写真から同じシールトを生成できます。公開先は `https://schiild.pickleballnavi.jp/`。Xserverには静的UIと画像だけを置き、Cloudflare WorkersとSQLite Durable Objectで共有API・参加状況・生成・抽選を処理します。スマホではページ全体を縦にスクロールできます。

`demo`ブランチ専用です。本番のM1〜M4、API、DB、Rust/WASMには接続しません。TypeScript生成エンジンと暫定32色は、このデモだけで使います。

## 1週間の利用例（2026年10月19日）

[ユーザー依頼] `/week/` は、200アトリエ・架空の1,000人が2026年10月13日〜19日に利用した閲覧専用の再現です。通常のアトリエ選択画面にも入口があります。上部の「見る人」で1,000人の視点を切り替え、所属アトリエ、投稿状況、開封、日付別GLOBAL、カレンダー、預かり作品、専有面積を確認できます。期間は固定し、6日分の過去と最終日途中の状態を再現しています。一部のアトリエは最終日の作品も生成済みです。

公開140・非公開60アトリエ、記録6,562件、完成作品1,201点を用意しました。各人の参加先は1〜3か所で、日ごとの投稿人数は720〜816人です。途中参加、未投稿の区画、全員が休む日、GLOBALに記録しない選択、預かり手の違いも含めています。GLOBALは明示的に記録した人だけを1人1日1ピクセルで配置します。日別の件数は `public/week/scenario.json` に記録しています。

写真素材から `scripts/generate-large-week.mjs` がデモ専用の生成・GLOBAL・面積集計処理をローカルで実行し、公開用の応答と画像だけを `public/week/` に保存しています。認証トークン・パスワード・内部ストアは書き出しません。再生成は `pnpm --filter demo demo:week` です。抽選結果は再生成ごとに変わり得ます。使われなくなった画像も自動削除しません。初回は小さな一覧と選んだ1人分だけを読み込み、GLOBALの共通画像・座標は日別ファイルから読み込みます。1,000人全員の詳しい記録は一括取得しません。

閲覧中は通常APIへ接続せず、端末保存も専用メモリーだけを使います。通常のアカウント・アトリエ・画像・言語設定は参照・更新・削除しません。新規作成、撮影、参加・脱退、名前の変更、アカウント削除は再現モードで行えません。「通常のデモへ」で実際の操作に戻れます。閲覧画面には架空の記録であることを常時表示します。

写真32点は [Lorem Picsum](https://picsum.photos/) が提供するUnsplash素材です。[Unsplash License](https://unsplash.com/license) に従って使用し、撮影者と元ページは `public/week/photos/credits.json` に記録しました。これは実際の利用者が撮影した写真や利用実績ではありません。参考デザインの写真は使用していません。

`week.test.mjs` は人数・期間・所属・画像・GLOBALの座標・面積・秘密情報の非出力を検証します。`week-browser.mjs` は通常データを残した状態での分離、APIへPOSTしないこと、視点切替、アーカイブ・開封・GLOBAL・検索・プロフィール・翻訳・画面幅を検証します。

## アーカイブとGLOBALの閲覧（デモ専用・2026年10月19日）

## LINEログイン（デモ専用・現在保留）

[ユーザー確認済み・2026年10月19日] LINEログインを保留します。公開環境の `LINE_LOGIN_CONFIG` に `paused: true` を設定し、ログイン・連携の導線を非表示にし、認可開始とコールバックのAPIも拒否します。Windows内の接続情報と既存のアカウント・投稿は維持します。ID・パスワードのログインは利用できます。再開時は接続先チャネルの確認後に `paused` を解除します。以下は再開に備えた実装の説明です。

[実装済み・現在保留] LINE連携の実装を残しています。WhatsAppとGoogleの新しい設定も保留中です。再開した場合、LINEで初めてログインするとアカウントを作り、次回以降は同じLINEから同じアカウントへ戻ります。既存のID・パスワードのアカウントへ連携する場合は、先にそのアカウントへログインし、プロフィールのLINEログインから連携します。表示名やメールアドレスだけではアカウントを結合しません。

LINE DevelopersのLINEログインチャネルでウェブアプリを有効にし、コールバックURLを `https://schiild.pickleballnavi.jp/?auth=line` に設定してください。一般の利用者に使ってもらう場合は、チャネルを公開する必要があります。要求スコープは `openid profile` だけです。メールアドレス・電話番号・友だち一覧にはアクセスしません。

Cloudflare WorkerのSecret `LINE_LOGIN_CONFIG` に `channelId`・`channelSecret`・`redirectUri` の3項目を持つJSONを設定します。秘密情報はチャット、Git、Expoの公開環境変数、Xserverへ入れません。接続設定がない間はLINEの導線を表示しません。手動の設定は `apps/demo` で `pnpm exec wrangler secret put LINE_LOGIN_CONFIG --config wrangler.jsonc` を実行し、JSONをCLIの入力欄へ渡します。ローカルの接続入力画面を使う場合、Channel secretはWindows資格情報マネージャーへ保存します。

認可コードはCloudflareで交換し、LINEの検証APIで署名・発行元・対象チャネル・有効期限・nonceを確認します。state、PKCE S256、5分で失効する一度限りのブラウザ別チャレンジ、IPごとの認証試行制限を付けています。戻りURLから認可コードとstateを除去し、LINEのアクセストークンは保存しません。LINE識別子はチャネルIDと合わせたハッシュだけを保存します。

LINEだけで作ったアカウントも設定から完全削除できます。ID入力と削除確認の後、同じLINEで再認証してから削除します。投稿・共同作品は従来どおり匿名の記録として残し、セッション・LINE連携・途中の認証情報は消去します。ID・パスワードとLINEの両方を連携したアカウントは、従来のパスワード確認で削除できます。

`line-auth.test.mjs` と `line-runtime.test.mjs` は、外部APIをモックしてメモリー・SQLite・workerdで認証、別ブラウザからの復帰、不正なstateや再利用の拒否、試行制限、アカウント削除を検証します。`line-browser.mjs` は6言語の導線、320/390/768px表示、認証の往復、URL消去、LINEでの削除を検証します。実際のLINEアカウントでの接続確認は、チャネル設定後に利用者が行います。

## 生成画像の解像度（デモ専用・2026年10月15日）

[ASSUMPTION / ユーザーの画質改善依頼に基づく変更] アトリエの新規生成・仮生成を128×128pxから256×256pxへ変更しました。BSPの構図は128単位の座標のまま保ち、各区画を2倍の寸法で元写真から再サンプリングします。既存画像を引き伸ばしたものではありません。暫定32色とピクセルアートの表示方法、1080×1080の撮影入力は維持します。GLOBALは1人1日1ピクセルを維持し、明示的にGLOBALへ記録した人数に応じた最小正方形へ配置します。本番M1〜M4には変更しません。

生成日ごとに `outputSize` を保存します。未生成の旧データは新しい256pxで生成し、完成済み・生成処理中の旧データは `outputSize` がなければ128pxとして扱います。保存済みの完成作品を再生成・上書きしません。専有面積は各作品の実画素数で集計し、新しい作品では同じ区画のpx数が4倍、構図に対する割合は同じになります。新旧の履歴が混在しても当時の画素数を合計します。

Xserverの保存口はアトリエ作品の128pxと256pxだけを受け付けます。Cloudflareの順次画像処理とブラウザ側の生成の双方に反映し、開封・カレンダーでも同じ画像を表示します。`resolution.test.mjs` と生成エンジンのテストでは細部の保持、旧作品のバイト列と面積の維持、256pxのPNG出力を確認します。workerd/PHPのテストでも生成・保存・読み出しまで通します。

## 友達との使い方

1. 「アトリエ ＋」から「アトリエをつくる」を開き、名前と定員を決めます。
2. 表示された招待リンクか8文字のコードを友達へ渡します。
3. 友達が「参加する」を押すと、当日から写真を記録できます。
4. 参加者が「このアトリエに1日1枚」から撮影し、確認画面で写真の送信を確定します。
5. 写真が集まったら、作成者が「シールトを生成する」を押します。現在の投稿数と受付終了の説明を確認すると、作品が生成されます。
6. 参加者は「ひらく」から同じ作品を開封できます。その作品はアーカイブにも残ります。各日付の「GLOBAL SCHIILD」から、その日の共有GLOBALを開けます。預かり手が他の人でも閲覧できます。
7. アトリエ選択画面の各行にある「アトリエを抜ける」で退会できます。ログインし直しても、抜けたアトリエは参加一覧へ復元されません。招待コードから再参加できます。

退会しても、投稿済みの区画・写真・完成作品・GLOBALのピクセルはそのまま残ります。作成者が抜けると、残っている最初の参加者へ生成権限を引き継ぎます。全員が抜けてもアトリエと記録は削除せず、最初に再参加した人が生成できるようになります。投稿済みの区画を別の参加者が使えるのは翌日からです。未投稿の区画は当日から再利用できます。同じ人が当日戻る場合は、自分の投稿済み区画へ戻れます。端末内アトリエの履歴もブラウザ内に残し、同じコードでの再参加時に復元します。

[ASSUMPTION / ユーザー承認済み] デモの退会・生成権限の引き継ぎ・再参加を追加します。元の投稿を取り消さず、日付ごとに当時の参加者と区画の対応を保存して、過去の作品を描き直さない実装です。退会は再参加できるため、追加の確認モーダルを置かず、一覧に結果を説明します。

生成後は、その日の写真を追加できません。翌日の受付はUTC 00:00（JST 09:00）に始まります。同じブラウザで同じ日に記録した写真は、複数のアトリエでも同じ画像を使います。写真の差し替えはできません。

## 今日のシールトの仮生成（デモ専用）

今日の画面の「今日のシールトを仮生成する」から、その時点で集まっている写真をすぐ画像にできます。共有アトリエでは参加者全員が使え、1枚以上の投稿が必要です。正式生成の前に何度でも試せます。投稿の受付は続き、正式作品・抽選・アーカイブ・GLOBAL・投稿済み区画は変更しません。「デモ専用・仮表示」を明示して表示し、戻る・再読み込み・日付変更・正式生成で仮表示を破棄します。画像はサーバーや端末のストレージへ保存せず、表示中だけメモリに置きます。生成失敗時に仮の代替画像を出しません。

## カメラが使えないとき

撮影画面の「許可の手順を見る」から、iPhone・iPad / Safari、Android / Chrome、PC / Chrome・Edge、その他のブラウザの手順を選べます。サイトの許可と端末側の許可を見直してから、同じ画面の「カメラを再確認する」で撮影を再開します。プレビューやアプリ内ブラウザで利用できない場合は、画面に表示したURLを通常のブラウザで開きます。権限拒否・カメラ未検出・起動失敗・非対応・安全な接続でない場合を区別します。撮影を離れた後に許可しても、そのリクエストのカメラは停止します。

[ASSUMPTION / デモ用文言] ユーザーが依頼したカメラ復旧導線として、Webブラウザの許可手順と失敗原因の案内を `demo.camera.*` に追加します。正式な権限説明と拒否見出しは `docs/copy.md` をそのまま使用します。WebページからOSやサイトの許可を変更するボタンにはせず、端末側での変更手順と再試行を提供します。

手順の参照元: [Chrome（Android）](https://support.google.com/chrome/answer/2693767?hl=ja&co=GENIE.Platform%3DAndroid)、[Safari（iPad）](https://support.apple.com/ja-jp/guide/ipad/ipad8ea0fc1a/ipados)、[Firefox](https://support.mozilla.org/en-US/kb/how-manage-your-camera-and-microphone-permissions)、[Windows](https://support.microsoft.com/en-us/windows/privacy/manage-app-permissions-for-a-camera-in-windows)。自動テストは擬似カメラと権限エラーを使用します。実機のOS設定の変更やカメラの物理的な故障は自動操作で検証できません。

## XserverとCloudflareへの反映

Cloudflare APIトークンは対象アカウントのWorkers編集権限に限定することを推奨します。Global API Keyを使う場合は登録メールアドレスも必要です。Windowsでは `LocalApiKeys/cloudflare` と `LocalApiKeys/xserver` に保存し、実行する子プロセスにだけ渡します。キーをチャット・Git・公開環境変数へ保存しません。

1. Xserverで `schiild.pickleballnavi.jp` と独自SSLを用意し、SSH公開鍵を登録します。SSHのホスト鍵を確認・記録してください。証明書検証やホスト鍵検証は無効化しません。
2. `apps/demo/scripts/configure-xserver.ps1` をPC上で実行します。画像ディレクトリは `/home/<server-id>/schiild-demo-images` のように、すべての `public_html` の外にします。設定と共有署名キーはアクセスを制限した `.deploy-private/` に保存されます。既存の署名キーを作り直さないでください。
3. 対象アカウントを `CLOUDFLARE_ACCOUNT_ID` に設定し、次を実行します。有料プランへの切り替えは不要です。利用量の上限に達すると制限されます。

```sh
pnpm install --frozen-lockfile
pnpm --filter demo exec wrangler deploy
```

4. `.deploy-private/storage-secret.txt` の値を、チャット外の伏せ字入力または標準入力でWorkerの `XSERVER_STORAGE_SECRET` に登録します。コマンドの引数に秘密の値を含めません。

```sh
pnpm --filter demo exec wrangler secret put XSERVER_STORAGE_SECRET
```

5. デプロイ結果のWorker URLに `/api/atelier` を付け、公開用環境変数を設定してUIを書き出します。以下はPowerShellの例です。この変数はAPIのURLのみで、秘密情報を含みません。

```powershell
$env:EXPO_PUBLIC_DEMO_API_URL = 'https://schiild-demo-api.black-field-ae8f.workers.dev/api/atelier'
node apps/demo/scripts/prepare-xserver.mjs
& apps/demo/scripts/deploy-xserver.ps1 -CheckOnly
& apps/demo/scripts/deploy-xserver.ps1
```

## アカウント・GLOBAL・設定

左上のSchiildアイコンはログイン状態を確認し、未ログインならログイン画面、認証済みならプロフィールへ進みます。IDは英小文字・数字・_・-で3〜24文字（先頭は英数字）、パスワードは12〜128文字です。ログインすると参加アトリエと作成者の生成権限を復元します。表示名を変更でき、預かり作品から開封ページへ移動できます。

パスワードは16バイトの個別ソルトとPBKDF2-HMAC-SHA256（100,000回）のハッシュだけをCloudflareに保存します。セッションは暗号学的乱数32バイト、有効期限7日、DBにはトークンのSHA-256ハッシュを保存します。ログアウト時にはサーバー側で無効化します。IDごとの試行上限は10分間5回で、同時試行も条件付き更新で数えます。公開APIでは認証操作をIPごとに1分10回までに制限します。メール確認、パスワード再発行は提供しません。アカウント削除の手順は下記に記載します。

共有GLOBALへの参加は、撮影の確定後の記録先画面で「今日のグローバルシールト」を選択した場合のみです。アトリエへの記録だけではGLOBALへ追加しません。1人1日1シールで、同日の別のシールへの差し替えはAPIでも拒否します。同じシールの再送は重複を作りません。アトリエの追加先とGLOBALは同時に選択でき、GLOBAL記録済みの日もアトリエへの追加は可能です。

選択した写真の平均色を暫定32色へ減色し、1人1ピクセルにします。GLOBALへ記録した当日のユニーク人数 N に対して一辺 ceil(sqrt(N)) の正方形PNGを生成し、0〜N−1の重複しない連番セルへ配置します。5人なら3×3、10人なら4×4で、最後の行の必要最小限だけを空きセルとして残します。同じ人の複数アトリエの投稿は同じGLOBALピクセルです。人数増加で一辺が変わる日は座標も再計算されますが、元の写真・色は変えません。全利用者に同じ画像を返し、当日の記録に合わせて更新し、翌日から固定します。従来のGLOBALメタデータは色と並び順を保持してコンパクト表示に対応し、元画像を削除・上書きしません。記録先に選ばなかった写真を過去のアトリエからGLOBALへ自動追加する処理は行いません。

拡大・ピクセル選択・自分の位置・面積の分母はAPIの outputSize に合わせます。XserverのGLOBAL保存口は1〜4096pxの正方形PNGを受け付け、写真1080pxとアトリエ作品128/256pxの制限は維持します。過去30日の端末内履歴と端末内で生成した作品は「サンプル作品」と表示し、共有GLOBALの集計に混ぜません。

共通の下部ナビゲーションはアトリエ選択・コード共有・アカウント・設定でも表示します。「アーカイブ」から日付ごとのGLOBALを選べます。設定の「開封・ズームの演出を省略する」はこのブラウザに保存されます。通知は未対応と表示します。Xserverは静的UIと署名付き画像保存のみ、認証と共有処理はCloudflare内です。

旧Netlifyサイトには今回のログイン機能を反映しません。新しいUIを利用する配置先はCloudflare APIを設定したXserver版です。

## アトリエごとの投稿と専有面積（デモ専用）

[ユーザー依頼・集計方法承認済み] 参加するアトリエごとにUTC日付につき1枚を撮影・確定できます。同じアトリエの確定済み写真は取り消し・差し替えできません。新規参加・作成・アトリエ切り替えによる写真の自動投稿は行いません。この仕様変更はデモだけに適用し、本番M1〜M4、要件定義書・正式文言は変更しません。説明・確認画面の文言はデモ専用キー／上書きで区別します。

撮影の確認画面で確定し、最初の記録が成功した後に「別のアトリエにも記録」へ進みます。撮影した写真を自動で選び、別の参加アトリエを名前・コンセプトの組で表示します。コンセプト未設定、または「あなたのお気に入りの一枚」が設定されたアトリエだけを追加先として選べます。その他のテーマは同じ構成のままグレー表示にし、APIと端末内の追加処理でも制限します。投稿済み・生成中・受付終了・対象日が異なるアトリエも選べません。「アトリエに戻る」で追加せず終了でき、最初の記録は残ります。今日の画面の転送アイコンは削除し、コード共有は三点を結んだ共有アイコン、開封アイコンは中央に配置します。

プロフィールの「今日の自分の投稿」からも、自分の当日写真と同じ条件のアトリエ・GLOBALを選択できます。元の写真のプレビューは本人だけに返します。複数の追加先はそれぞれ確定し、成功・失敗をアトリエごとに表示します。退出後も自分の当日投稿を再利用できます。翌日には前日の写真を再利用できません。共有写真は内容別の保存キーにし、再利用時には画像を複製せず既存の写真を参照します。従来の保存キーも引き続き読めます。
