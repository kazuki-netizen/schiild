# Schiild デモ — 友達とつくるシールト

アトリエを作成して友達を招待し、それぞれのカメラで撮った写真から同じシールトを生成できます。公開先は `https://schiild.app/`。静的UIはCloudflare Workers Assets、画像・アカウント・参加状況は既存のSQLite Durable Objectへ保存し、生成・抽選もCloudflare Workersで処理します。Xserverへの実行時依存はありません。スマホではページ全体を縦にスクロールできます。

`demo`ブランチ専用です。本番のM1〜M4、API、DB、Rust/WASMには接続しません。TypeScript生成エンジンと暫定32色は、このデモだけで使います。

## 1週間の利用例（2026年10月19日）

[ユーザー依頼] `/week/` は、200アトリエ・架空の1,000人が2026年10月13日〜19日に利用した閲覧と一時的なアトリエ参加ができる再現です。公開アトリエの一覧・検索と招待コードから参加できます。参加先・人数はその画面を開いている間だけ端末内に保持し、再読み込みすると元の利用例に戻ります。参加先の既存作品は閲覧できますが、過去の投稿・預かり作品・専有面積を参加者本人のものとして引き継ぎません。撮影などの変更は引き続き通常のデモで試します。通常のアトリエ選択画面にも入口があります。上部の「見る人」で1,000人の視点を切り替え、所属アトリエ、投稿状況、開封、日付別GLOBAL、カレンダー、預かり作品、専有面積を確認できます。期間は固定し、6日分の過去と最終日途中の状態を再現しています。一部のアトリエは最終日の作品も生成済みです。

公開140・非公開60アトリエ、アトリエへの記録6,562件、完成作品1,201点を用意しました。各人の参加先は1〜3か所で、アトリエへの日ごとの投稿人数は720〜816人です。GLOBALの投稿人数は日ごとに800〜1,000人の範囲でランダムに決め、今回は7日合計6,309件です。同じ日を再閲覧しても人数や配置は変わりません。GLOBALだけに記録する人も含み、実際のデモと同じ生成・座標処理を使います。途中参加、未投稿の区画、全員が休む日、GLOBALに記録しない選択、預かり手の違いも含めています。GLOBALは明示的に記録した人だけを1人1日1ピクセルで配置します。日別の件数は `public/week/scenario.json` に記録しています。

写真素材から `scripts/generate-large-week.mjs` がデモ専用の生成・GLOBAL・面積集計処理をローカルで実行し、公開用の応答と画像だけを `public/week/` に保存しています。認証トークン・パスワード・内部ストアは書き出しません。再生成は `pnpm --filter demo demo:week` です。抽選結果は再生成ごとに変わり得ます。使われなくなった画像も自動削除しません。初回は小さな一覧と選んだ1人分だけを読み込み、GLOBALの共通画像・座標は日別ファイルから読み込みます。1,000人全員の詳しい記録は一括取得しません。

閲覧中は通常APIへ接続せず、端末保存も専用メモリーだけを使います。通常のアカウント・アトリエ・画像・言語設定は参照・更新・削除しません。新規作成、撮影、参加・脱退、名前の変更、アカウント削除は再現モードで行えません。「通常のデモへ」で実際の操作に戻れます。閲覧画面には架空の記録であることを常時表示します。

写真32点は [Lorem Picsum](https://picsum.photos/) が提供するUnsplash素材です。[Unsplash License](https://unsplash.com/license) に従って使用し、撮影者と元ページは `public/week/photos/credits.json` に記録しました。これは実際の利用者が撮影した写真や利用実績ではありません。参考デザインの写真は使用していません。

`week.test.mjs` は人数・期間・所属・画像・GLOBALの座標・面積・秘密情報の非出力を検証します。`week-browser.mjs` は通常データを残した状態での分離、APIへPOSTしないこと、視点切替、アーカイブ・開封・GLOBAL・検索・プロフィール・翻訳・画面幅を検証します。

## アーカイブとGLOBALの閲覧（デモ専用・2026年10月19日）

カレンダーの切り替えは「GLOBAL SCHIILD」「アトリエ」です。GLOBAL側は記録が存在する日だけを一覧にし、タップした日の共通作品を開きます。アトリエ側は現在所属するアトリエの生成済み記録を日付ごとにまとめ、日付をタップすると作品が横に並びます。タッチの横スワイプと矢印で選び、そのアトリエ・日付の作品を開きます。月移動、戻る、キーボードのフォーカス保持は維持します。

[ユーザー依頼] 未投稿のアトリエ区画とGLOBALの余った区画は、UTCの日付ごとに白・青・ミント・杏色・ラベンダー・砂色から選ぶ淡いモザイクです。同じ日は全アトリエとGLOBALで同じ基調色、隣り合う日は異なる色になり、閲覧や再読み込みで変わりません。空欄のモザイクの粒は、写真部分と同じ出力画像の1pxです。GLOBALの利用例も拡大用画像の1pxに揃えます。XserverのJPEG自動変換で粒が崩れないよう、利用例の作品PNGはクエリー付きURLと `no-transform` ヘッダーで元の画素を保持します。撮影済みのシールには適用しません。UIの背景は白一色です。既存の実利用者の完成作品は保存済み画像を維持し、新しい生成・仮表示と架空の1週間の画像に適用します。GLOBALの1人1日1論理ピクセルは維持し、拡大すると各区画の実際のシールを表示します。GLOBAL画面にはアトリエ作品やピクセルの順番の案内を表示しません。「ここがあなたの区画です」は平均色の見本ではなく、本人がGLOBALへ選んだ実際のシール画像です。タップすると全体表示から約1.6秒かけて自分の区画へズームします。手動操作・画面サイズ変更で演出を中断でき、動きを抑える設定では即時に移動します。色のコードや色見本は表示しません。自分の座標は本人のシール画像と常にセットで表示し、別のシールをタップしても変わりません。選択した別のシールは、その画像と座標を同じ詳細枠に表示します。表示座標は左上を (1, 1) とし、右が x、下が y の正方向です。自分・他のシール・空欄とも各軸は1から始まります。保存済みデータと配置計算は0始まりのまま保ち、表示時だけ各軸に1を加えます。GLOBALへ選ばなかった写真や、参加していない非公開アトリエの作品は公開しません。利用例の未完成作品は仮表示と明記します。過去の実利用者の完成画像は再生成・削除しません。

## GLOBALの実画像と個人座標（デモ専用・2026年10月19日）

[ユーザー依頼] 利用例も色の配列だけにせず、各人がその日にGLOBALへ選択した実写真1枚を対応するセルへ配置したPNGを生成しています。日別の人数Nに対し一辺 ceil(sqrt(N)) の正方形、1人1セル、重複しない連番座標です。1セル64×64pxの画像を合成しますが、本人の座標・選択・面積の分母は従来の論理ピクセルで扱います。`schiils` の位置と画像、各人のx/y、合成PNGの各セルが一致することを全件検証します。素材32点は架空の利用例で再利用します。1,000枚の異なる写真を撮影した実績ではありません。

通常デモでは、GLOBALへ明示的に選ばれた写真だけをCloudflareの非公開保存領域へ保持します。`global.schiils` は画面内の位置を最大9件ずつ受け取り、その日の記録にある写真の256pxサムネイルだけを返します。アトリエ名、参加者の識別値、元の保存キーは返しません。アカウント削除後もユーザー確認済みの匿名記録として残ります。古いGLOBALは同じハッシュの元写真が残っている場合だけ取得し、ない場合は取得不可を表示します。推測した画像は作りません。

ピンチ・スワイプ・マウスで画面内の実写真だけを読み込み、タップすると写真と座標を確認できます。拡大・縮小ボタン、倍率表示、スライダーは表示しません。本人のシール画像をタップすると、同じ閲覧領域を全体から本人の座標へ移動・拡大します。従来の色だけを拡大する別画像・拡大鏡は使いません。位置計算、全区画への到達、明示的に選んでいない写真の除外、旧記録、取得失敗と再試行、実Worker/PHP保存経路を検証しています。本番M1〜M4には変更しません。

## 利用者のLINE登録・ログイン（デモ専用）

利用者は自分のLINEアカウントから登録・ログインできます。初回はSchiildのアカウントを自動作成し、次回以降は同じアカウントと所属アトリエへ戻ります。既存のID・パスワードのアカウントへ連携する場合は、先にそのアカウントへログインし、プロフィールのLINEログインから連携します。表示名やメールアドレスだけではアカウントを結合しません。LINE公式アカウント管理者としてのログインとは別の機能です。WhatsAppとGoogleの新しい接続は保留を維持します。

[公開設定済み・2026年10月21日] Schiild専用プロバイダー `2005662016` 内に、ウェブアプリ用のLINEログインチャネル `2012141224` を作成・公開しました。戻り先は `https://schiild.app/?auth=line` です。接続情報をWindows資格情報とCloudflare Secretへ保存し、`paused: false` へ変更しています。公開アプリの「LINEでログイン」から、このチャネルのLINE認証画面へ到達することを確認しました。同日、利用者本人から実際にLINEでログインできたことの確認を受けています。初回登録・再ログイン・既存アカウントとの連携はSQLiteを含む自動テストで検証しています。

LINE DevelopersのLINEログインチャネルでウェブアプリを有効にし、コールバックURLを `https://schiild.app/?auth=line` に設定してください。一般の利用者に使ってもらう場合は、チャネルを公開する必要があります。要求スコープは `openid profile` だけです。メールアドレス・電話番号・友だち一覧にはアクセスしません。

Cloudflare WorkerのSecret `LINE_LOGIN_CONFIG` に `channelId`・`channelSecret`・`redirectUri` の3項目を持つJSONを設定します。秘密情報はチャット、Git、Expoの公開環境変数、Xserverへ入れません。接続設定がない間はLINEの導線を表示しません。手動の設定は `apps/demo` で `pnpm exec wrangler secret put LINE_LOGIN_CONFIG --config wrangler.jsonc` を実行し、JSONをCLIの入力欄へ渡します。ローカルの接続入力画面を使う場合、Channel secretはWindows資格情報マネージャーへ保存します。

再開・停止の設定は `scripts/deploy-line.mjs` にまとめています。Git対象外の `.deploy-private/line-login.json` から公開のChannel IDを読み、Channel secretはWindows資格情報から子プロセスの `SCHIILD_LINE_SECRET` へ渡します。ファイルや引数へ秘密の値を書きません。`--check` は設定の形式だけを確認し、LINE側での有効性やチャネル公開状態は確認しません。有効なLINEログインチャネルと戻り先を確認してから `--enable` を実行します。

```sh
node apps/demo/scripts/deploy-line.mjs --check
node apps/demo/scripts/deploy-line.mjs --enable
# 停止するとき
node apps/demo/scripts/deploy-line.mjs --pause
```

反映には `CLOUDFLARE_ACCOUNT_ID` とCloudflareの認証情報が必要です。スコープ付きの `CLOUDFLARE_API_TOKEN`、または `CLOUDFLARE_API_KEY` と `CLOUDFLARE_EMAIL` を子プロセスに渡します。秘密の値をコマンドライン引数へ含めません。これらの操作はLINE設定だけを更新し、アカウント・アトリエ・写真・作品を初期化しません。

認可コードはCloudflareで交換し、LINEの検証APIで署名・発行元・対象チャネル・有効期限・nonceを確認します。state、PKCE S256、5分で失効する一度限りのブラウザ別チャレンジ、IPごとの認証試行制限を付けています。戻りURLから認可コードとstateを除去し、LINEのアクセストークンは保存しません。LINE識別子はチャネルIDと合わせたハッシュだけを保存します。

LINEだけで作ったアカウントも設定から完全削除できます。ID入力と削除確認の後、同じLINEで再認証してから削除します。投稿・共同作品は従来どおり匿名の記録として残し、セッション・LINE連携・途中の認証情報は消去します。ID・パスワードとLINEの両方を連携したアカウントは、従来のパスワード確認で削除できます。

`line-auth.test.mjs` と `line-runtime.test.mjs` は、外部APIをモックしてメモリー・SQLite・workerdで認証、別ブラウザからの復帰、不正なstateや再利用の拒否、試行制限、アカウント削除を検証します。`line-browser.mjs` は7言語の導線、320/390/768px表示、認証の往復、URL消去、LINEでの削除を検証します。実際のLINEアカウントでの接続確認は、チャネル設定後に利用者が行います。

## 生成画像の解像度（デモ専用・2026年10月15日）

[ASSUMPTION / ユーザーの画質改善依頼に基づく変更] アトリエの新規生成・仮生成を128×128pxから256×256pxへ変更しました。BSPの構図は128単位の座標のまま保ち、各区画を2倍の寸法で元写真から再サンプリングします。既存画像を引き伸ばしたものではありません。暫定32色とピクセルアートの表示方法、1080×1080の撮影入力は維持します。GLOBALは1人1日1ピクセルを維持し、明示的にGLOBALへ記録した人数に応じた最小正方形へ配置します。本番M1〜M4には変更しません。

生成日ごとに `outputSize` を保存します。未生成の旧データは新しい256pxで生成し、完成済み・生成処理中の旧データは `outputSize` がなければ128pxとして扱います。保存済みの完成作品を再生成・上書きしません。専有面積は各作品の実画素数で集計し、新しい作品では同じ区画のpx数が4倍、構図に対する割合は同じになります。新旧の履歴が混在しても当時の画素数を合計します。

アトリエ作品は128pxの旧作品と256pxの新作品を読み出せます。Cloudflareの順次画像処理とブラウザ側の生成の双方に反映し、開封・カレンダーでも同じ画像を表示します。`resolution.test.mjs` と生成エンジンのテストでは細部の保持、旧作品のバイト列と面積の維持、256pxのPNG出力を確認します。workerd/PHPのテストでも生成・保存・読み出しまで通します。

## 友達との使い方

1. 「アトリエ ＋」から「アトリエをつくる」を開き、名前と定員を決めます。
2. 表示された招待リンクか8文字のコードを友達へ渡します。
3. 友達が「参加する」を押すと、当日から写真を記録できます。
4. 参加者が「このアトリエに1日1枚」から撮影し、確認画面で写真の送信を確定します。
5. 写真が集まったら、作成者が「シールトを生成する」を押します。現在の投稿数と受付終了の説明を確認すると、作品が生成されます。
6. 参加者は「ひらく」から同じ作品を開封できます。その作品はアーカイブにも残ります。各日付の「GLOBAL SCHIILD」から、その日の共有GLOBALを開けます。預かり手が他の人でも閲覧できます。
7. アトリエ選択画面の各行にある「アトリエを抜ける」で退会できます。ログインし直しても、抜けたアトリエは参加一覧へ復元されません。招待コードから再参加できます。

退会しても、投稿済みの区画・写真・完成作品・GLOBALのピクセルはそのまま残ります。作成者が抜けると、残っている最初の参加者へ生成権限を引き継ぎます。全員が抜けてもアトリエと記録は削除せず、最初に再参加した人が生成できるようになります。投稿済みの区画を別の参加者が使えるのは翌日からです。未投稿の区画は当日から再利用できます。同じ人が当日戻る場合は、自分の投稿済み区画へ戻れます。端末内アトリエの履歴もブラウザ内に残し、同じコードでの再参加時に復元します。

[ASSUMPTION / ユーザー承認済み] デモの退会・生成権限の引き継ぎ・再参加を追加します。元の投稿を取り消さず、日付ごとに当時の参加者と区画の対応を保存して、過去の作品を描き直さない実装です。退会は再参加できるため、追加の確認モーダルを置かず、一覧に結果を説明します。

生成後は、その日の写真を追加できません。翌日の受付はUTC 00:00（JST 09:00）に始まります。同じブラウザで同じ日に記録した写真は、複数のアトリエでも同じ画像を使います。写真の差し替えはできません。

## アカウント・GLOBAL・設定

左上のSchiildアイコンはログイン状態を確認し、未ログインならログイン画面、認証済みならプロフィールへ進みます。IDは英小文字・数字・_・-で3〜24文字（先頭は英数字）、パスワードは12〜128文字です。ログインすると参加アトリエと作成者の生成権限を復元します。表示名を変更でき、預かり作品から開封ページへ移動できます。

パスワードは16バイトの個別ソルトとPBKDF2-HMAC-SHA256（100,000回）のハッシュだけをCloudflareに保存します。セッションは暗号学的乱数32バイト、有効期限7日、DBにはトークンのSHA-256ハッシュを保存します。ログアウト時にはサーバー側で無効化します。IDごとの試行上限は10分間5回で、同時試行も条件付き更新で数えます。公開APIでは認証操作をIPごとに1分10回までに制限します。メール確認、パスワード再発行は提供しません。アカウント削除の手順は下記に記載します。

共有GLOBALへの参加は、撮影の確定後の記録先画面で「今日のグローバルシールト」を選択した場合のみです。アトリエへの記録だけではGLOBALへ追加しません。1人1日1シールで、同日の別のシールへの差し替えはAPIでも拒否します。同じシールの再送は重複を作りません。アトリエの追加先とGLOBALは同時に選択でき、GLOBAL記録済みの日もアトリエへの追加は可能です。

選択した写真の平均色を暫定32色へ減色し、1人1ピクセルにします。GLOBALへ記録した当日のユニーク人数 N に対して一辺 ceil(sqrt(N)) の正方形PNGを生成し、0〜N−1の重複しない連番セルへ配置します。5人なら3×3、10人なら4×4で、最後の行の必要最小限だけを空きセルとして残します。同じ人の複数アトリエの投稿は同じGLOBALピクセルです。人数増加で一辺が変わる日は座標も再計算されますが、元の写真・色は変えません。全利用者に同じ画像を返し、当日の記録に合わせて更新し、翌日から固定します。従来のGLOBALメタデータは色と並び順を保持してコンパクト表示に対応し、元画像を削除・上書きしません。記録先に選ばなかった写真を過去のアトリエからGLOBALへ自動追加する処理は行いません。

拡大・ピクセル選択・自分の位置・面積の分母はAPIの outputSize に合わせます。Cloudflareの画像処理は1〜4096pxの正方形GLOBALを扱い、写真1080pxとアトリエ作品128/256pxの制限は維持します。過去30日の端末内履歴と端末内で生成した作品は「サンプル作品」と表示し、共有GLOBALの集計に混ぜません。

共通の下部ナビゲーションはアトリエ選択・コード共有・アカウント・設定でも表示します。「アーカイブ」から日付ごとのGLOBALを選べます。設定の「開封・ズームの演出を省略する」はこのブラウザに保存されます。通知は設定から種類別に有効・無効を選べます。UI・画像・認証・共有処理はすべてCloudflare内です。

旧Netlifyサイトには今回のログイン機能を反映しません。新しいUIを利用する配置先は `schiild.app` のCloudflare版です。

## Web Push（デモ専用・2026年10月20日）

[ユーザー依頼] ログイン後の設定で、アトリエのシールト完成、GLOBAL SCHIILDの完成、参加アトリエへのほかの人の投稿を個別に切り替えられます。3種類の初期値はオンですが、端末の許可と「この端末で通知を受け取る」を押すまでは購読も配信も行いません。種類の設定はアカウント全体、受信の許可は端末ごとです。通知には投稿者の名前・写真・未投稿者の情報を含めません。投稿した本人にはその投稿の通知を送りません。

配信直前に設定・参加状態・セッションを再確認します。ログアウト・退出・期限切れ・通知オフで保留中の配信を止め、アカウント削除では購読・設定・配信記録を消去します。既に端末の通知欄やPushサービスへ渡った通知は取り消せません。言語を切り替えると、この端末の通知もその言語になります。/week/は実際の通知を送信せず、購読もしません。
